# 0.23.1 验证记录

日期：2026-11-03。[文档导航](README.md)

状态：本次自动回归、类型检查、生产构建、原生窗口对照与两个真实 Electron 入口通过；目标电脑的本版效果仍待复测。本记录保留与 [0.23.0](release-validation-0.23.0.md) 的区别，不沿用其全量测试数字作为本版结果。

## 输入证据

用户反馈 0.23.0 已能流畅使用，提供 `thinking-gpu.json`、`idea-gpu.json` 和 `性能诊断报告-0.23.0.md`。模型 GPU 绘制用时较短，低帧率窗口几乎没有应用主动跳帧；这支持继续检查回调之外的工作和交付节奏，不足以证明 DWM 是唯一根因。

原始数据中，thinking 独立采集 29 个样本、GPU 均值 1.460ms；另一轮包含 idle/thinking/idea 共 29 个样本。以 `intent:idea` 结束的窗口约 21–31fps，后面约 60fps 的窗口已回到 idle。CPU 生命周期均值、窗口均值、帧间隔 P95、GPU 捕获期不能混算；完整说明与字段表见[性能诊断](render-performance.md)。

用户另行报告 DSH 桥重载后 `promptProtocol:2`、纯正文消息生效。本次实机确认限于该消息格式，不代表所有 DSH 接口、取消路径或表演功能重新做过端到端验收。

## 同生产路径的本机对照

对照为 0.23.0 与 0.23.1，相同原生 main/preload/React、真实模型和本机 240Hz 显示器。八个场景覆盖待机、思考、想到了、讲述，以及聊天窗口打开／关闭；每场景采样 6.5 秒，保留 `setOpacity(254/255)` 的既有遮挡修复。

| 指标 | 0.23.0 | 0.23.1 |
|---|---:|---:|
| 八场景累计 `setShape` 调用 | 446 | 51 |
| 八场景采样期重复 `moveTop` 调用 | 674 | 0 |
| 模型绘制速率 | 约 60fps | 59.83–60.13fps |
| 帧间隔 P95 | 约 16.7–17ms | 16.7–17ms |

`setShape` 调用减少 88.57%；这是一项原生调用数量结果。两版在本机原本都约 60fps，所以不能据此声称本机提帧，或推算目标电脑的帧率改善。新路径八阶段均未记录到长任务，仍不证明目标机剩余等待完全来自 DWM。

八张 `capturePage` 独立捕获图以 alpha≥32 筛选有色像素，与实际应用的 native shape、实时工具窗口排除区域逐像素检查，未覆盖像素均为 0。该阈值检查不覆盖更透明的边缘像素，也不能替代所有点击操作。另人工检查四个场景，未发现新增框裁切；半身场景底部属于预先移出 viewport 的摆放。精确命中仍使用实时模型数据，旧最小保护边距及最大 2P 包络限制保留。

原始本机对照结果位于忽略目录 `output/compositor-probe/candidate/comparison.json`。未连接或改动用户 DSH，会话纯正文的实机确认仍仅来自上面的用户报告。

## 目标电脑复测

1. 保持当前更顺的档位、相同角色大小和相同缓存／兼容快照选项；一次只改变一个变量。
2. 固定思考、想到了与待机分别留足稳定窗口，记录聊天窗口显示／隐藏情况。跨动作边界的窗口不能直接代表单一姿态。
3. 复制性能诊断，先比较 `sampleRafFps`、`sampleFps` 与 `sampleSkippedFrames`，再看同一报告窗口的 CPU 均值；GPU 计时按捕获状态与阶段分别解释。
4. 检查摸头、胸前点击、敲盆、拖动缩放、屏幕边缘、悬浮球和聊天窗重叠，以及隐藏后恢复；不能只凭 setShape 次数减少就判定交互正确。

目前没有证据可将剩余帧间隔全部量化为 DWM 等待；本机保持 60fps 也不能替代目标 16GB 电脑的复验。
