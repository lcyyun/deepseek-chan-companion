# DeepSeek-chan（大肥鱼）模型适配记录

分析对象为 DeepSeek-chan 的“大肥鱼”模型。这是运行用导出包，不含 Cubism 编辑工程。原始模型保持原样，平台从本地目录读取，不重新发布模型包。

## 已核实的资源

共 44 个文件、60.46 MiB；36 个 JSON 均能解析。包含 1 个 moc3、5 张贴图、23 个表情、8 个动作、131 个物理组、40 条 VTube Studio 参数映射和 28 个快捷键。CDI 有 509 个唯一参数条目（含辅助参数和分隔符）、21 个参数组、148 个部件，不能将条目数理解为独立动作数。

model3 直接引用的 moc、贴图、physics、cdi 全部存在。它没有登记 Expressions/Motions；文件实际存在于 Exp3/Animation，平台需构造索引。LipSync 组为空，需显式映射嘴型。`items_pinned_to_model.json` 没有挂件。存在 VBridger 设置文件，但这不构成平台运行依赖。

## 参数与计算顺序

头部控制输入是 `AngleX/Y/Z`，通过物理生成 `ParamAngleX/Y/Z`。身体控制为 `PositionX/Y/Z`，前倾为 `LeanInput`。行为层先生成上游控制值，运行时再计算物理。不要逐帧覆盖物理输出或将 `Emotion/Emotion2` 当作可直接控制的情绪按钮。

眼球使用 `ParamEyeBallX/Y`，眼开使用 `ParamEyeLOpen/ROpen`，笑眼使用 `EyeSmile`，嘴部使用 `ParamMouthOpenY`、`JawOpen`、`ParamMouthForm`。VTS 中的映射范围是已有校准信息，不等于 moc 的真实参数边界；真实边界和默认值必须从运行时读取。

实际 Cubism Core 读取已确认：`AngleX/Y/Z`、`PositionX/Y/Z`、`LeanInput` 都是 [-30,30]、默认 0；`ParamEyeBallX/Y` 和 `ParamMouthForm` 为 [-1,1]、默认 0；`ParamEyeLOpen/ROpen` 为 [0,1.5]、默认 1。行为测试使用这次运行时导出的边界验证跟随与动作连续性；生产控制器仍每次读取当前模型的边界，而非依赖写死的测试数据。

`ParamMouthOpenY` 有 CDI 描述、VTS 映射、脱捕动作曲线和嘴唇/舌头/脸颊物理输入四重证据；`JawOpen` 为独立下巴通道，参与脸颊物理。说话口型以实际播放音频能量驱动嘴开和下巴，情绪层独立维持嘴形和笑眼。

`ParamA/I/U/E/O/ParamSilence` 有明确的 `VoiceA/I/U/E/O/VoiceSilence` VTS 映射，但没有物理输入输出或已有动作曲线。它们不是只有名字的猜测，也尚未通过运行时形变验证。默认禁用五元音写入；只有逐项视觉校准通过才能启用。五元音不等于完整中文音素口型。静音时不假定 ParamSilence 能强制关闭所有嘴部参数。

## 行为与打断

基础呼吸和眨眼、视线与头姿、情绪、语音、手势分层合成。大模型只下发语义动作；本地每帧计算连续参数。思考小动作具有冷却、不连续重复、可立即取消。持续思考组合嘴边食指、稍微抬头、轻皱眉、嘟嘴和轻微身体摇动；完成时短暂伸指、张嘴笑、抬眉并轻微放大瞳孔，再进入回答。它们不自行切换衣服。

成功回复消费本轮思考状态，先播放一次 `idea`，约 1.8 秒后才开始段落表演与音频。完成动作留 0.2 秒衔接余量，避免同一帧先收手再为正文重新举起。前端用请求 ID 和可取消的轮次等待处理新请求、停止、重复回复、迟到事件及无声模式；provider 错误不触发完成动作。`cuddle`、`think`、`idea` 在小动作面板均有对应验收按钮。

打断取消本轮后续动作和表情，关闭嘴型并进入聆听，已保持的手势用对应关闭动作回收。音频和网络层还需使用同一轮次 ID 丢弃迟到的旧音频/命令，并停止当前播放；行为控制器本身不拥有音频设备。

### 预设动作接线与 VTS 对照修正

生产 manifest 的动作/表情名称去掉了 `.motion3.json` / `.exp3.json` 后缀。早期行为调用仍携带后缀，而播放器精确查找名称，导致几乎所有作者动作、表情找不到资源；点头直接驱动参数，因此仍能轻微变化。行为层现使用 canonical 名称，测试使用与真实 manifest 一致的严格资源表，避免仅用无条件接受名称的 mock 漏掉问题。

作者 VTS 配置的三个“打开”快捷键都是 TriggerAnimation + StopsOnLastFrame=true，没有另绑定“竖食指开”等表情。打开 motion 自带 Movement1/2/3 选择器和整套手臂曲线；播放器必须保持完整末帧。不能额外把同名开关表情 Add 1 叠到仍在播放的过渡动作上，否则会提前切换手型或重复相加。回收按作者对应关闭 motion 和原时长执行。害羞、思考等表现另外组合作者的“脸红”“加载”表情。

状态快照与表演命令分开处理：相同 idle 快照本来就是空操作；但从 listening/thinking 变成 idle 的服务快照，早期会取消刚收到的显式 perform。现在状态切换只清掉自动思考动作，显式表演按自己的时长完成，除非收到 stop/reset。点头、摇头和思考头姿的幅度已提高，最终仍按运行时返回的真实参数边界限制。

### 持续摸头

前端调用 `setPetting(true, { x, y, speed, intensity })`，其中 x/y 为头部区域的归一化坐标 [-1,1]（x 向右、y 向下），speed 为 [0,1] 的归一化移动速度，intensity 默认 0.8。移动时持续更新；释放或取消时调用 `setPetting(false)`。按住静止也保持闭眼、开心嘴形和呼吸，移动时轻微蹭手，停止移动后蹭手速度自然减弱。前端负责单击最短反馈和 pointer capture。

摸头是本地交互层，不调用大模型、不改对话 state。它暂时优先控制头姿、视线和眼部表情，并用作者脸红参数 key7 的较低权重叠加轻微红晕；音频驱动的嘴开和下巴继续工作。松手后约 0.6–0.8 秒缓动回到原状态，思考请求尚未结束时继续思考。stop 会同时解除摸头。头部变化仍写 AngleX/Y/Z 等上游输入，在物理计算前应用。

新一次 pointer-down 用 `newContact:true` 重置连续接触计时，pointermove 不重置；短点击的视觉余韵不会累计成两秒长按。加载表情在真实思考期间保留，包括摸头期间。双臂与脸部都平滑释放，仍在思考时恢复脸旁竖指。

头部检测先比较未裁切模型坐标的部件高度，再映射到画布。旧版把放大后被屏幕裁切的 head/body 比例用于判断，导致正常头部被错误替换为顶部 22% 的备用区域；此路径会使可见脸部点击失灵。新版在视图缩放后立即刷新几何，并保留可见头部。原生窗口保护形状使用 DIP，扣除悬浮球和聊天窗的覆盖区域，包括拖动模式和指针捕获期间。

闭眼使用独立接触进度，约 0.7 秒平滑到两个眼开参数的真实最小值（本模型为 0），不再因默认 intensity=0.8 停在半睁状态。闭眼不接管音频口型：`ParamMouthForm` 保留开心嘴形，`ParamMouthOpenY` 和 `JawOpen` 持续由实际播放音频驱动。释放后双眼平滑睁开，不在一帧内从 0 跳到 1。

### 全局指针跟随与动作收尾

`setPointerTracking(true, { x, y, speed, travel })` 接收本地鼠标输入；x/y 为相对屏幕或头部中心的归一化方向 [-1,1]，x 向右、y 向下，speed/travel 为 [0,1] 的速度与偏移量。该接口不自行读取桌面输入；前端和桌面进程负责按住左键时持续发送、释放/隐藏时调用 `setPointerTracking(false)`，以及停止后在鼠标真正松开前抑制重新激活。`isPointerTracking` 可用于检查保持状态。

偏移越大，头姿和躯干输入越大；阻尼弹簧保留方向反转时的速度，平滑的 `AngleX/Y/Z`、`PositionX/Y/Z`、`LeanInput` 再进入作者物理。眼球一起跟随，但不会直接写 `ParamAngleX/Y/Z`、身体物理输出、头发或衣物物理参数。松手约 0.8–1.2 秒回到基础呼吸姿势。摸头优先于跟随，摸头期间持续更新跟随目标；松开头部而全局左键仍有效时恢复跟随。stop/reset 同时取消两个持续交互。

语义动作使用短暂进入和尾段渐出包络；尾段最长 0.8 秒，头姿、视线、眉眼情绪与非语音嘴形逐渐回到基础状态，到期移除 action 时已经接近零贡献。表情从尾段开始交给运行时平滑关闭。手臂回收继续播放作者完整的对应关闭动画，运行时负责 stop 到资源加载的姿态保持、全部手臂曲线的连续衔接以及回到动态 IDLE 的尾部混合，不能只渐变 Movement 开关。

### 双臂撒娇与脸旁竖指的实际验证

以下边界来自真实 moc 的 Core 参数导出，姿势通过独立 Cubism 预览验证。`Param37`（动画开关）和 `Param38`（动画双手开关）均为 [0,1]、默认 0，单独开启不能得到双手抚胸。原模型只有一侧完整作者抚胸组；0.7 在运行时复用整组手掌、袖口和前臂作为另一侧。

| 用途 | 参数与已验证目标 | 真实范围 / 默认值 |
|---|---|---|
| 作者单侧抚胸 | Movement2=1；Param62=0.034、Param59=0.476、Param60=0.86、Param61=0.002 | Movement2 [0,1]；其余 [-1,1]；默认均 0 |
| 作者竖指选择器 | Movement1=0、Movement3=1、Param40=1 | [0,1]；默认均 0 |
| 思考时食指靠嘴边 | Param36=0、Param39=0.6、Param41=0.79、Param42=0、Param43=0；AngleX=18、AngleY=8、AngleZ=2 附近小幅摇动 | 手臂 [-1,1]；头姿 [-30,30]；默认均 0 |
| 双侧撒娇抚胸 | 原作者抚胸组；Param60=0.82，让指尖留出间距 | [-1,1]；默认 0 |

0.6 单独前置并缩小 `Part130` 的手掌，未能保持它与侧后方袖口的连接，用户截图暴露了这一问题。0.7 移除这种做法，以作者完整抚胸手、袖口、前臂为一体构造另一侧，保留原 UV 与整条连接结构。对称轴由衣领宝石 `ArtMesh394` 与胸前下钮扣 `ArtMesh407` 的实时中心确定，跟随身体倾斜。使用 `Param60=0.82` 调整整个前臂，使双手指尖分开；不能仅挪动手指或手掌来修补。

将食指移近嘴边后，原绘制顺序会让手指藏进脸和头发后方。运行时只把 `Part56` 的手掌/食指后代（九个 drawable）临时移到前景，不移动 `Part55` 的袖口或整条手臂；重新排列为唯一、连续的 render order，绘制后立即还原，退场保留短暂余韵。原始 moc 文件不变。`Param43=-0.8` 是旧版撒娇右手出现手指交叠的来源，不能把任意中间值当作自然握拳。手臂数值能合法写入不代表组合形态自然，必须实看校准。

这些 Param36/39/40/41/42/43 与 Param62/59/60/61 是作者动作使用的直接形变曲线；`Movement1/2/3` 还会经 PhysicsSetting128 驱动 Param35 手臂切换物理。基础姿势在 motion 后、物理前混合，不改写 Arm/Forearm 等物理输出。释放时混合权重降低，再用对应关闭 motion 回收；保持和回收必须涵盖整套手臂曲线，不能只取消 Movement 选择器。

镜像源仅限 `Part52` 完整抚胸组。作者关闭动画在约 0.54 秒切换到普通手臂后仍继续放下，不能在此处直接恢复右侧垂手。临时把原右臂输入按 `Param36←Param62`、`Param39←Param59`、`Param41←Param60`、`Param42←Param61` 同号跟随，保持它本来的绘制层级，衔接完整回收；`Param37/38` 均保持 0。镜像手臂的存续独立于脸部淡出，等作者收回结束才释放。第二渲染通道使用独立遮罩缓存、共享原贴图，每帧还原临时顶点、透明度和动态标志。

收回阶段从姿势叠层移除 Movement1/2/3、Param37/38/40，让作者动画独占手型切换；只渐退角度。残留极小的旧选择器也会造成半透明双手重影。排队中的新姿势要等对应手势真正开始，脸部表情和加载提示则不必等待。

摸头持续超过 2 秒进入上述撒娇组合，脸红 `key7` 默认由短摸约 0.28～0.35 渐变到 0.75；松开后缓动释放，语音口型保持独立。独立校准参考位于 `vendor/arm-audit-v2/mirror-spread-0.82.png`、`mirror-body-1.png` 与 `lips-think-w0.png`。校准不修改原模型，正式接入仍需用生产渲染核对进入、保持和打断退出。

### 表情细节与瞳孔

思考使用实际上游输入 `Mouthpucker=0.7`、`MouthPuckerWiden=-0.35`、`MouthFunnel=0.12`、`CheeckPuff=0.18`，配合 `ParamBrowLY=-0.24`、`ParamBrowRY=-0.2`。`idea` 采用嘴形约 0.8、嘴开 0.5、下巴 0.28、双眉 0.6、`BrowInnerUp=0.18`；动作包络负责进入和收尾。摸头优先闭眼微笑，说话时嘴开仍由实际音频控制，思考的嘟嘴逐渐退出。

`PupilX/Y` 是透视物理输出；`SHOCKEYE` 和 `ShockL/R` 在本模型的实看校准中也没有产生可用的瞳孔缩放。运行时以眼球部件 `Part43/35/140/145` 的可见网格中心做小幅缩放，保留眼白、眼睑、原 UV 和裁剪关系，每帧绘制后还原顶点，避免累计形变。完成思考时约放大 8%，随后平滑归位。独立真实渲染测试确认能产生可见像素变化，复位后与基准逐像素一致。

### 画布、钢盆敲击与局部物理

原生宠物窗口覆盖当前显示器的工作区，模型采用独立的屏幕坐标中心与绝对倍率。缩放围绕光标计算中心；0.7 在所有倍率都允许部分出屏，只保留至多 80 DIP 的可抓取区域，不再把较小模型整只推回。位置保存包含同模型、同倍率的实际 `fullBody` 相对中心边界，避免重启时用参考矩形将有效角落位置推回。`placementRevision` 对齐渲染几何，丢弃旧版本命中区，并用未裁切的 `fullBody` 预测下一帧保护区域。移动边框和原生保护区域裁入当前屏幕，只有按住捕获期间保护整段拖动。球和聊天窗保持屏内，锚点在主动移动/缩放时更新，避免跟着呼吸、尾巴抖动。

作者 `钢盆.exp3.json` 使用 `key10=1`，部件为 `Part80`；`圈圈眼.exp3.json` 使用 `key3=1`。脸部盆影是独立 `ArtMesh157`，每帧仅将其透明度乘以用户阴影浓度（默认 0.35），绘制后还原；盆身不变。盆开关保存在桌面设置中，停止和动作 reset 不会摘盆。盆顶使用独立可见几何命中区，避免宽盆边缘超出原头部椭圆后无法点击。摘盆恢复原摸头逻辑。

每次 `pointerdown` 只触发一个 `knockBasin()`，重新开始最长 0.66 秒的局部惊吓包络，不排队、不累积力量。短时冲击层位于作者表情之后、物理之前，控制圈圈眼、互斥眼型、眉毛与轻微头姿；说话时保留音频嘴开控制。`LControl/RControl` 实际由 PhysicsSetting82/84 根据眉毛生成，直接在物理前写它们会被覆盖。因此耳弹采用物理计算后的短时增量叠加：在原有 LEar/REar1/2/3 结果上加有限小脉冲，按真实边界限制，每帧重新计算，不累积、不替换基础物理。停止、隐藏或摘盆立即清除短时反应。

敲盆声是本地生成的非谐波金属共振与短促撞击声，不需要 TTS 或联网。最多保留四次余响和四个 12 毫秒淡出，搭配动态压缩；延迟恢复的音频设备不会重放过期点击。音效与语音分析器分开，敲盆不会误驱动说话口型。

胸部仅调节 PhysicsSetting64/65（输出 ChestX/ChestY）的非根粒子，保留半径、延迟、输出比例及 PhysicsSetting66。柔软度 1 对应作者原稿，默认 1.15 对应 Mobility 增加 0.01、Acceleration 乘 0.95；整体范围 0～2，Mobility 最大 0.96。运行时平滑调整已创建粒子的系数，保留位置、速度与模拟缓存，不重建物理实例。此前默认系数的固定 60fps 对比测得 ChestX2 峰值提高约 15%、ChestY2 约 9%，5 秒后接近静止，ChestY4 完全一致。参数只改内存，不改变体型、衣服或原始 physics3 文件。

调节面板使用共享 `model-tuning.mjs` 校验六项设置；IPC 合并部分更新、限制有限数值和范围、持久化后向三个窗口广播。身体动作和鼠标跟随系数在行为层平滑过渡，脸红只调整摸头与撒娇浓度。敲盆在表情冲击层增加 PositionX/Y/Z/LeanInput 的衰减颤抖，乘以身体幅度并按模型真实边界限制；每次点击替换起点，不累积力量。音量独立作用于金属声输出总线，静音也取消尚在等待音频设备恢复的旧敲击，不影响语音。

### 0.8 常规表情与作者小零件

`src/shared/expressions.mjs` 保存 25 种独立、完整复位的面部配方。每项经真实 Cubism 渲染校准，并检查 Core 参数范围；不写身体、眉角、眼球透视等物理输出。面部叠层位于作者表情之后、敲盆冲击之前，避免作者 IDLE 或遗留 exp3 参数覆盖新表情。

| 作者参数 | 实际素材 | 使用示例 |

| key1 | 脸部黑影 | speechless 无语 |
| key2 | 眼泪 | teary 泪汪汪 |
| key3 | 白色圈圈眼 | dizzy 晕乎乎、敲盆 |
| key4 | 爱心眼 | love 心动 |

说话时 `expressionCues` 走独立面部通道，按实际音频播放时间或静音阅读进度推进；不会重新触发手臂。固定“想到了”与预设撒娇的面部在说话提示出现时让位，实体摸头仍保留优先。停止、切换回复或重置会取消旧通道。

悬浮球按下后使用屏幕 DIP 判断 5 DIP 拖动阈值，指针捕获保持整段拖动；释放只有未越过阈值才开关聊天。独立位置持久化，在模型移动和缩放时保持，恢复跟随时清除此位置。球始终限制在可用屏幕内，原生模型保护形状实时扣除它的当前位置。

### 0.9 轻点反应与窗口内选择菜单

胸前命中区来自可见 `Part86`、`Part88` 后代网格的实际边界，在未被屏幕裁切的坐标中构造收紧椭圆；随缩放、身体姿势和物理移动更新，不能用画布固定百分比。仅完成 450 毫秒内、位移不超过 8 DIP 的左键轻点才调用 `tapChest()`，按下时忙碌的点击不能在释放时补触发。长按、取消、拖动模式和头部交互分别处理。

反应序列持续 4.8/4.4/4.4 秒，按连续时间采样姿态与面部，不排队、不设置延迟回调。整轮自然完成才晋级，第三轮封顶，60 秒无接受点击回第一轮；预览不写点击进度。真实摸头、敲盆、思考和新动作取消反应，中止不晋级。反应控制上游头姿、视线、身体输入与面部，语音仍独占嘴开、下巴，不额外播放手臂 motion。末段渐退，身体幅度继续受用户设置限制。

表情选择使用渲染窗口内的 combobox/listbox，固定定位根据客户区可用空间选择上/下展开，限制高度并滚动；没有原生弹出窗口。产品文案只描述表情，素材映射保留在本技术文档中。

`knockSound` 是单独校验的 `basin`/`pipe` 枚举，与数值滑条范围分开；选择持久化并广播。钢管 MP3 从随包静态目录加载、缓存解码，使用与原敲盆音相同的音量、压缩与复音上限。声音切换、停止和静音都会使旧待播请求失效。

### 0.10 安抚与心动回路

第三轮自然完成后停止重复播放责怪，转为等待安抚。只有之后的新一轮真实摸头接触持续至少 0.3 秒才解锁心动；之前的摸头和松手余韵不会解锁。松手后下一次有效胸前轻点进入约 5 秒心动反应，使用爱心眼、温柔红晕及更明显的呼吸起伏。自然结束清空点击进度，下一次重新从第一轮开始。

心动沿用独立反应通道，呼吸只增加 `ParamBreath` 与上游 `PositionY` / `LeanInput`，按真实边界裁切并受 `bodyMotion` 控制，不直接写胸部或躯干物理输出。停止、隐藏、摸头、敲盆或新请求会取消当轮效果；语音仍独占嘴开、下巴。`previewChestReaction(4)` 只供独立检查，不推进真实点击状态。

### 0.11 身体联动与独立肢体预览

新身体动画仍基于现有单侧抚胸与竖指，不把模型当作自由骨骼。`body-animation.mjs` 用归一化关键帧描述六组准备、保持、强调和收回过程，只有已校准的 Param36/39/41/59/60 叠加小幅连续增量。手型选择器不随幅度滑条缩放；换姿态时只平滑角度，收手仍交给完整作者 motion，避免半透明重手。

眼神、头部与躯干以不同响应速度更新，躯干依照已经平滑的头姿跟随，原物理继续计算衣物、头发等余动。`expression` 预览与 `body` 预览相互独立；真实触摸优先。手动完整动作也优先于自动说话节奏，只有内部标记 `replyIntro` 的思考完成动作会把手势直接交给第一句。

隔离真实模型 QA `tests/body-production.cjs` 检查六组各五个过程帧、实际参数边界、结束收回、撒娇镜像交接，以及小表情卡片不会重启手臂。新增形变仍须实际查看，不能仅凭参数合法判断无穿模。
