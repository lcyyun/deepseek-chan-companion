# 回复节奏：先短句，再展开

桌宠的语音适合即时交流。回答保留有用结论和关键理由，较长的步骤、解释、背景放在可展开详情中。这里的“短”不是把一篇长回答按字符截断。

## 当前协议

模型返回结构化 JSON：

```json
{
  "segments": [
    {
      "text": "可以。先把模型加载起来，再接上对话和声音。",
      "intent": "explain",
      "emotion": "gentle",
      "gesture": "pointer",
      "expressionCues": [
        { "at": 0, "emotion": "gentle", "intensity": 0.7 }
      ]
    }
  ],
  "details": "更完整的步骤与原因放在这里。",
  "sources": []
}
```

`segments` 用于气泡、聊天正文和逐段朗读。每段一两句完整的话，最多三段；`details` 点击“展开说说”后显示，不朗读。动作是语义提示，由本地行为控制器执行，不能写任意代码或任意模型参数。

## 长度预算

| 设置 / 问题 | 提示目标 | 语音软上限 |
|---|---|---:|
| 短句陪伴 | 通常一两句，约 30–90 个汉字；简单回应可以更短 | 合计 140 字符 |
| 适中 / 一般问题 | 约 60–130 个汉字 | 合计 220 字符 |
| 适中或详细 / 复杂问题 | 约 120–220 个汉字，完整版放详情 | 合计 320 字符 |

问候通常限制为一段；普通请求最多两段；非简短档的复杂请求最多三段。代码用关键词做轻量预算分类，不是语义理解器，因此实际完整性仍依赖模型。不会为了凑字数把“谢谢”“你好”扩写成长篇，也不会用最低字数冒充回答质量。

超过软预算时，服务会尝试一次语义压缩修复，让模型重新组织可朗读的摘要；保留原完整内容供展开查看。修复仍不合格时返回明确错误，避免悄悄按字符切掉后半句。原始输出超过三段时，额外段落完整转入详情。单段超过安全硬上限的异常输出可能直接被拒绝。

## 朗读与表演

- 每段开始时切换讲话状态，表情与肢体由独立时间线跟随实际播放进度；不再用字数估计一段完整肢体动作的时长。
- 音频播放器测量实际播放的声音强弱；本地每帧合成嘴开、下巴和情绪嘴形。网络等待不应触发假口型。
- 口型与微笑分开控制，因此可以笑着说话。手势有完整的打开、保持和回收过程。
- 说话肢体由现有 intent/gesture 本地规划，短句最多一个主要动作。长句仅在部分语义子句处强调；相邻相同姿态可保持，不每句收手再举手。文字子句比例只是近似定位，不是声学重音识别。
- 过短的音频不强行播放完整手臂进出；暂停不推进肢体时间线，迟到帧跳过过期动作。用户可调节自动手势频率，设为 0 时只保留表情和基础活动。
- 思考时的小动作有冷却并避免连续重复；开始回答或收到停止指令后取消旧事件。
- 停止或新一轮回复使用轮次标识使旧播放队列失效，避免过时回答稍后重新开口。
- `expressionCues` 按角色自己这段话的语气安排脸部变化，不用用户文本中的单个情绪词做机械判断。25 种可用表情由共享目录提供给提示词、输出结构和 MCP 能力查询；旧提供方不返回 cues 时，沿用本段 `emotion`。
- `at` 是实际朗读进度的 0～0.9，不是请求发出后的秒数。最多四项，通常只用一两项；归一化会去重、过滤未知表情和过密提示。播放时至少相隔 750 毫秒，结束前 400 毫秒不再换脸。静音模式按本段阅读进度执行。
- 表情提示只控制面部，不重播手臂动作。真实音频独占嘴开和下巴；摸头、敲盆临时覆盖对应面部，加载环与常驻道具独立。用户的逐表情微调和整体幅度应用在最终本地合成层。

## 来源和联网事实

普通兼容 API 没有默认搜索工具。提示词会明确这一事实，服务也会清除该通路输出的检索来源，不能因为模型生成了一个网址就认定它查过网页。

Codex 通路单独记录是否尝试搜索以及是否完成搜索。搜索完成状态不等于每条结论都已自动核验；来源必须与回答内容相关。未检索时不应声称“刚刚查证”。陪看正文来自浏览器主动分享，与外部网页搜索是两种不同证据。

接口模式、错误处理和当前限制见 [智能体接入](agent-integration.md)。长度与来源逻辑由 `server/protocol.mjs`、`server/adapters.mjs`、`server/service.mjs` 实现；行为与音频同步分别在 `src/shared/behavior.mjs` 和 `src/renderer/audio.ts`。
