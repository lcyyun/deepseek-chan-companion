# 回复节奏：先短句，再展开

核对版本：**0.18.0** · 最近核对：**2026-11-01** · [文档目录](README.md)

桌宠的语音适合即时交流。回答保留有用结论和关键理由，较长的步骤、解释、背景放在可展开详情中。这里的“短”不是把一篇长回答按字符截断。

本文描述当前聊天回复、外部朗读命令和本地播放策略；动作选择可先读[模型控制快速指南](model-control-quickstart.md)。0.18 的来源解析没有改变已有的开场组合与语音时钟规则。

## 先区分两条入口

- **桌宠聊天窗口 `/api/chat`**：服务先检查 `providerEffective` 和 `chatAvailable`，可用后才请求模型并执行下面的长度预算。自动模式优先接入 DSH 聊天桥；仅有 MCP 表演连接不能发起聊天，Codex 仅手动选择。DSH 断线时保留来源与草稿，不降级到其他提供方。
- **外部智能体 `avatar_speak` / HTTP `type:"speak"`**：直接提交已经组织好的文本和表现，不再调用聊天模型做语义压缩。接口允许的 6,000 字符是安全上限，不是建议朗读长度；外部智能体仍应自行遵循一两句的节奏。新命令会替换旧朗读，不是追加播放队列。

对话来源与语音来源相互独立。当前默认声音是在线晓伊；选择 DSH 不要求改成某个专用 TTS。语音配置和错误分流见[智能体接入](agent-integration.md)。

## 当前协议

模型返回结构化 JSON：

```json
{
  "segments": [
    {
      "text": "可以。先把模型加载起来，再接上对话和声音。",
      "intent": "explain",
      "emotion": "gentle",
      "gesture": "pointer",
      "bodyAnimation": "auto",
      "combination": "auto",
      "expressionCues": [
        { "at": 0, "emotion": "gentle", "intensity": 0.7 }
      ]
    }
  ],
  "details": "更完整的步骤与原因放在这里。",
  "sources": []
}
```

`segments` 用于气泡、聊天正文和逐段朗读。每段一两句完整的话，最多三段；`details` 点击“展开说说”后显示，不朗读。动作是语义提示，由本地行为控制器执行，不能写任意代码或任意模型参数。当前严格输出 schema 要求每段包含 `bodyAnimation` 与 `combination`；旧提供方省略时服务按 `auto` 兼容。

`bodyAnimation` 可选 `auto`（本地安排）、`none`（本段不安排说话肢体）或 12 个具体动画 ID，完整列表见 [DSH 指南](dsh-agent-guide.md#44-12-组肢体动画)。长解释和选项比较都可用 `talk`，安慰可用 `chest-both`。具体动画自带手型，优先于旧 `gesture` 提示；脸部语气仍由 `emotion/expressionCues` 决定。

`combination` 选择每段的完整表情与动作组合，可为 `auto/none` 或 [12 个组合 ID](dsh-agent-guide.md#45-12-个开场组合)。默认只在 `bodyAnimation` 也是 `auto` 或省略时，根据该段的准确意图和兼容情绪选择；不靠文本情绪词猜测，也不默认重返 `think` 长等待。显式组合可以先于显式独立肢体播放；连续动作在连续段重复同一组合（三次点头=三段 `agree`），最多三段。整个流程都不为了动作拉长文字。

## 用选择指南表达语气

能力目录中的 `tags` 用于检索，`useWhen/avoidWhen` 用于判断这句话是否适合该表现；它们不加入回复 JSON，也不触发额外调用。`recommendedEmotions/recommendedBody` 是少量备选搭配，组合的搭配指组合后的剩余口播，不能同时派发表情、身体和完整组合来争抢通道。

先写自然、够用的短答，再决定表现。优先熟悉 `agree` 开心点头、`explain` 讲个重点、`shy` 有点害羞、`think` 冥思苦想、`idea` 想到了、`cuddle` 撒娇捧胸；根据赞同、说明、含蓄、思索、新点子或亲昵语境选择，不强制轮换。`think` 仍需显式指定，单纯后台计算继续使用 `thinking` 状态。普通事实可以保持 `neutral`，无需动作的段落用 `bodyAnimation:none, combination:none`。

系统提示采用 `formatPerformanceGuide({includeCatalog:true})` 的紧凑标签、场景与短规则；完整避免场景与推荐搭配仍由能力查询提供。提示信息更清楚不代表应该多写话或多换表情：一条连贯的 `speak`、一两个合适的表情，通常比密集动作更自然。

## 长度预算

| 设置 / 问题 | 提示目标 | 语音软上限 |
|---|---|---:|
| 短句陪伴 | 通常一两句，约 30–90 个汉字；简单回应可以更短 | 合计 140 字符 |
| 适中或详细 / 一般问题 | 约 60–130 个汉字 | 合计 220 字符 |
| 适中或详细 / 复杂问题 | 约 120–220 个汉字，完整版放详情 | 合计 320 字符 |

问候通常限制为一段；普通请求最多两段；非简短档的复杂请求最多三段。代码用关键词做轻量预算分类，不是语义理解器，因此实际完整性仍依赖模型。不会为了凑字数把“谢谢”“你好”扩写成长篇，也不会用最低字数冒充回答质量。

超过字符或段数软预算时，服务会尝试一次语义压缩修复，让同一提供方重新组织可朗读的摘要；复杂问题只答“嗯／好的”等空泛确认且没有详情时，也会触发修复。修复不再请求搜索，原完整内容保留供展开查看。仍不合格时返回 `SPEECH_BUDGET_EXCEEDED`，不悄悄按字符切掉后半句。原始输出超过三段时，额外段落完整转入详情；聊天回复的单段超过 1,200 字符则直接拒绝。

## 朗读与表演

- 声音真正开始时才进入讲话状态，表演跟随实际播放进度；不再用字数估计一段有声肢体动作的时长。首段若选中组合，先在语音开头同步播放组合，再交给独立的表情与肢体时间线。
- 组合要求首段真实音频时长至少为“预设时长 + 0.4 秒”；太短直接跳过，不加长声音、不加空等。已选组合替代旧的思考完成 `idea` 前导，避免先后重复两次开场；未选中时保留原思考完成提示。
- 音频播放器测量实际播放的声音强弱；本地每帧合成嘴开、下巴和情绪嘴形。网络等待不应触发假口型。
- 口型与微笑分开控制，因此可以笑着说话。手势有完整的打开、保持和回收过程。
- `bodyAnimation:auto` 结合 intent/gesture 和正文选择动作，短句最多一个主要动作；较长的举指讲解统一可选为 `talk`。具体动画也可以由智能体显式指定，左右均按画面方向解释。
- `talk` 覆盖交给独立肢体的实际语音时段，不在开头几秒后停止。手臂轻柔强调与停顿交替，头部、躯干协调响应；相邻相同动画和手型可保持，不每句收手再举手。普通短动作仍在少量语义节点出现。文字子句比例只是近似定位，连续动作的内部节拍也不是声学重音识别。
- 过短的音频会把开场预设动作压缩进实际语音，而不是直接丢弃；迟到的首帧仍跳过，避免重播。实际音频时钟暂停时不推进肢体时间线和连续动作节拍。用户可调节自动手势频率，设为 0 时只保留表情和基础活动；`bodyAnimation:none` 只关闭对应段落的自动肢体。
- 思考时的小动作有冷却并避免连续重复；开始回答或收到停止指令后取消旧事件。
- 停止或新一轮回复使用轮次标识使旧播放队列失效，避免过时回答稍后重新开口。
- `expressionCues` 按角色自己这段话的语气安排脸部变化，不用用户文本中的单个情绪词做机械判断。25 种可用表情由共享目录提供给提示词、输出结构和 MCP 能力查询；旧提供方不返回 cues 时，沿用本段 `emotion`。
- `at` 是实际朗读进度的 0～0.9，不是请求发出后的秒数。有开场组合时，独立表情时间线在组合之后开始，进度指剩余语音部分。最多四项，通常只用一两项；归一化会去重、过滤未知表情和过密提示。播放时至少相隔 750 毫秒，结束前 400 毫秒不再换脸。静音模式按阅读进度执行。
- 需要停留的脸红/害羞/窘迫/惊讶：台词尽量约 30 字以上，在 `0、约0.45、约0.85` 锚定相近情绪，强度约 `0.8–0.85 → 0.65–0.75 → 0.55–0.6`；单段最多四项，不再叠加。跨段延续优先长台词加多锚点，不靠增加段数，避免动作重入和口型重置。
- 爱心眼 `love` 是表白级，只在用户明确表达爱意、亲昵告白或主动要求时使用；每轮最多一次，强度约 `0.7–0.85`。普通感谢、夸奖、好消息、工作讨论和悲伤严肃场景改用 `happy/joyful/gentle/playful`，不要用爱心眼冒充热情。
- 表情提示只控制面部，不重播手臂动作。真实音频独占嘴开和下巴；摸头、敲盆临时覆盖对应面部，加载环与常驻道具独立。用户的逐表情微调和整体幅度应用在最终本地合成层。

## 无声和失败时的节奏

关闭“朗读简短回复”时，每段按本地阅读时长推进表情与肢体：当前为 `文字长度 × 150ms`，限制在 2.2～10 秒。这只是无声展示策略，不表示已经合成或播放声音，也不会伪造音频口型。

语音合成或设备播放失败时会显示“语音未播放”并改为阅读，不静默改用另一家语音服务。如果已播放一部分，阅读从最后的音频坐标继续，避免从零重播组合或冻结单调时间线。完成思考但未选中开场组合时，仍可先播放约 1.8 秒“想到了”过渡；失败的聊天请求和停止操作不会触发这段完成动作。

## 来源和联网事实

普通兼容 API 没有默认搜索工具。提示词会明确这一事实，服务也会清除该通路输出的检索来源，不能因为模型生成了一个网址就认定它查过网页。

Codex 通路单独记录是否尝试搜索以及是否完成搜索。DSH 则由聊天桥按已配置的 `searchTools` 和成功工具结果回传相应标志；没有授权工具时不宣传搜索可用。搜索完成状态不等于每条结论都已自动核验；来源必须与回答内容相关。未检索时不应声称“刚刚查证”。陪看正文来自浏览器主动分享，与外部网页搜索是两种不同证据。

接口模式、错误处理和当前限制见 [智能体接入](agent-integration.md)。长度与来源逻辑由 `server/protocol.mjs`、`server/adapters.mjs`、`server/service.mjs` 实现；行为与音频同步分别在 `src/shared/behavior.mjs` 和 `src/renderer/audio.ts`。
