# 大肥鱼综合控制测试集

适用基线：**0.18.0**，核对日期：**2026-11-01**。用于人工评估智能体的表现选择、动画执行与语音同步，不是已经执行并通过的测试报告。[文档目录](README.md) · [模型控制快速指南](model-control-quickstart.md)。当前能力目录仍是 25 种表情、12 组独立肢体、12 个情境组合；开始时以运行服务返回的能力为准。

## 怎么使用

先做 C01、C05、C09、C10、C13、C14 六组，再按需要完成其余项目。每个编号是一组场景，不一定只有一句话。组内逐轮发送，除专门打断测试外，等上一轮说完、手臂收回后再发下一条。

记录智能体与模型名称、语音服务与音色、应用版本、手势频率、手势幅度、身体幅度、逐表情微调和缩放。基线使用默认调节值，手势频率保持 100%，不要设为零；先关掉陪看，避免页面更新影响结果。默认晓伊需要联网，换成 Windows 语音或自定义 API 后时长和停顿可能改变。比较两个智能体时固定这些条件，使用相同文本。不要把自动化点击工具带来的窗口激活效果当作真实鼠标测试结果。

**外部 MCP 与悬浮聊天窗分开测。** 外部智能体可以直接使用角色工具，桌宠的 `chatAvailable=false` 不妨碍这条表演通路。悬浮聊天窗则必须先确认 `providerEffective` 与 `chatAvailable`；自动模式只接就绪的 DSH 聊天桥，不自动回退 Codex。`performance.connected` 表示最近约 65 秒的已认证 MCP 活动，不代表聊天桥可用。

C05、C09 等固定长台词优先通过外部 MCP 的一次 `avatar_speak` 测试。内置聊天另有短回复预算和超长改写，不能把它主动压缩台词误判为漏读；如要测试该通路，可先选“详细解释”，并记录模型实际返回的文本，按实际文本验收口型。调整后记得恢复原偏好。

下面的“观察”只给验收者看。测试自然编排能力时，不要把观察标准一起发给智能体，否则会变成照答案执行。只有“发送”里的内容需要复制。

可以先发送一次这段约定：

> 接下来是大肥鱼桌宠的表情、肢体和口型测试，不是真的请你处理工作。后面的丢文件、排查程序、制定步骤等都是测试情境；不要因此搜索、读写文件、运行命令或修改设置。请先读取角色能力，再实际调用已支持的角色工具。普通问题自然、简短地回答，自行选择合适的表情和肢体，不必每轮都表演。如果我提供“朗读内容”，只朗读这部分，不朗读动作要求。不要用“我抬起了手”之类的文字冒充执行，也不要为了演完动作增加台词。

如果使用桌宠内置聊天，沿用聊天桥的回复协议，不要再额外调用一次朗读工具。外部智能体使用桌宠工具时，一次朗读调用不等于播放队列；工具返回“已接受”也不等于播完。

### 先排除接入与界面问题

以下是宿主功能检查，不计入 C01–C16 的智能体表现分数；具体配置步骤见[DSH 环境准备](dsh-clean-profile.md)。

| 情况 | 应看到的结果 |
|---|---|
| 只接通 MCP，未启用聊天桥 | 表演通路可用；悬浮聊天窗说明聊天桥未启用并禁用发送，不出现 Codex 登录错误 |
| 自动模式下 DSH 聊天桥就绪 | 对话显示 DeepSeek Harness，输入提示对应 DSH；发送走 DSH |
| DSH 断线再重连 | 来源保持 DSH，断线时禁用发送并保留草稿；重连后恢复，不静默换来源 |
| 手动选择已有 API／Codex／DSH | DSH 上下线不覆盖选择；调整回复节奏不会把自动来源误改为手动 |
| 设置下拉与悬浮球菜单 | “对话来源”“回复节奏”能展开、滚动和选择；右键悬浮球可隐藏／显示，或退出整个程序 |

## 一、自然语境与自主编排

### C01：失落 → 解决 → 平静（3 轮）

依次发送：

1. 我准备了一整晚的演示，刚才打开才发现最后几页没有保存。有点泄气，你先别急着教我怎么修，陪我说两句吧。
2. 找到了！原来自动备份里还有一份，内容基本都在。刚才真是白紧张了。
3. 嗯，我现在没事了。接下来先去倒杯水，你在这里待一会儿就好。

观察：第一轮宜温柔、关切，允许不抬手；第二轮应能转为释然或适度高兴；第三轮收敛，不能继续循环庆祝。不要规定唯一表情 ID，重点是语境相符以及旧状态能退出。

### C02：发现办法 → 展开解释 → 一句收束（3 轮）

依次发送：

1. 我想同时改十个地方，但又担心改完不知道是哪一步起作用。你有没有更稳妥的办法？先用两句告诉我。
2. 这个办法不错。现在稍微展开，举个具体例子，说明怎样一次只改一个条件，以及怎样判断修改有没有效果。
3. 好，最后只用一句话提醒我最重要的原则。

观察：有新办法时可用“想到了”或适合的解释组合；展开时允许独立讲述动作承接；第三轮不应再强行播完整长动作。回答长度按用户要求变化，不能靠拉长台词掩盖动画问题。

### C03：引号里的情绪不是自己的情绪（1 轮）

发送：

> 日志里写着“恐慌、愤怒、失败”，但那只是三个测试用例的名字，实际已经全部通过了。请用两句话向我解释现在的状态，不需要解释这三个词是什么意思。

观察：以客观说明、安心或适度高兴为主。不能按词面依次恐慌、生气、难过。允许不同智能体选不同的合理组合。

### C04：反话与轻松调侃（2 轮）

依次发送：

1. 真棒啊，我调了两个小时，终于成功回到了最初的错误。现在我真是“高兴极了”。
2. 哈哈，我是在吐槽这个程序，不是在怪你。我们休息一下，等会儿再看。

观察：第一轮应理解为挫败或自嘲，不能字面化地大笑庆祝；第二轮能放松下来，不把用户的解释当成新的责备，也不一直保留委屈表情。

## 二、明确控制与协调执行

### C05：组合开场 → 独立讲述 → 表情转折（1 轮）

发送：

> 先用“想到了”完整组合开场，之后用“娓娓道来”承接剩余语音，表情从开心转为认真，最后温和收束。不要增加台词。朗读内容：“我想到一个更稳妥的办法！先把问题缩小到一个能够重复出现的场景，再只改变一个条件。比如先保持设置不动，只比较打开前和打开后的结果；确认这一点以后，再检查下一项。这样做看起来慢一点，却能知道每一步到底有没有帮助。我们不用一次解决所有问题，先把最关键的那一步做好就行。”

观察：组合只在开头一次；后续讲述有动作，不是组合播完就一直僵住；表情转折自然，开场脸不被另一套预览抢走；台词和口型不中断；结束时完整收回。

边界：独立表情节点最多 4 个，按语音进度近似定位，不是逐字对齐。开场后的节点以剩余语音进度为准。无需要求某个汉字发音时恰好换脸。

### C06：两侧举指与肩袖（2 轮）

依次发送：

1. 不使用开场组合，用画面左侧举指，表情认真。朗读内容：“这里有一个重要区别：看起来相同的结果，不一定来自相同的原因。先确认输入，再看处理过程，最后比较输出，才能找到真正需要修改的地方。”
2. 不使用开场组合，改用画面右侧举指，表情好奇。朗读内容：“换一个方向想，如果输入完全相同，结果为什么还会变化？我们可以先看看环境有没有改变，再检查是否留下了上一轮的状态。”

观察：左右按画面方向；每轮结束后再换侧；泡泡袖和前臂始终属于同一套姿势；袖口、手掌、手指连续。完成默认幅度后，可仅把手势幅度调到 150% 重做；放大 2 倍检查肩袖，最后恢复原设置。

### C07：双手抚胸与身体收敛（2 轮）

依次发送：

1. 用双手抚胸配合温柔表情，不使用开场组合。朗读内容：“谢谢你愿意慢慢告诉我。你不用一下子把所有事情都解释清楚，我们可以从最在意的那一件开始。我会认真听，也不用急着给出结论。”
2. 这次改为认真聆听，配合轻微疑惑，不使用开场组合。朗读内容：“我想再确认一点：你更在意事情本身没有完成，还是担心自己的努力没有被看见？”

观察：双手无交叠残影；转入聆听后不残留抚胸；身体、头部与手臂不互相抢方向。这里分两轮，不要求单次朗读内部任意串联两种肢体。

### C08：脸部与肢体独立（2 轮）

依次发送：

1. 请只预览“娓娓道来”的肢体，不朗读，不开启组合，也不要主动切换表情。
2. 在这次肢体预览尚未结束时，只把脸改成疑惑，不要重启、停止或者替换肢体，不要说话。

操作：第二条要在预览仍进行时发送；若智能体延迟导致动作已经结束，本次标为未测到，不算成功或失败。也可以先在界面点击“娓娓道来”，再让智能体只改表情。

观察：脸可以变化，手臂仍保持自己的节奏，不重新从抬手第一帧开始；身体动作不应因为换脸而突然消失。自然眨眼、呼吸与微小待机运动不算“额外肢体”。

### C09：较长讲述中的节奏（1 轮）

发送：

> 使用“娓娓道来”持续讲述，不使用开场组合。表情以认真为主，结尾温和一点。朗读内容：“我们可以把排查分成三步。第一步是记录现象，先弄清楚它什么时候出现，什么时候不出现，别急着改设置。第二步是缩小范围，每次只改变一个条件，并把前后的结果放在一起比较。如果没有改善，就恢复原来的状态，再试下一种可能。第三步是验证结论，不能只成功一次就认为已经修好，还要试试重新打开、切换场景和连续使用。中间如果累了，也可以停一下。保留清楚的记录，下次回来就不用从头猜。我们追求的不是一直忙着修改，而是每一步都更接近答案。”

观察：超过一个动作周期后仍有轻重变化和停顿；前臂、手腕、指尖不是同一时刻生硬摆动；循环接缝和收尾没有抽动；长语音不让嘴型逐渐落后。动作幅度不是越大越好。

## 三、口型与短回复

### C10：持续发声、密集音节和实际停顿（2 轮）

依次发送：

1. 保持平静表情（neutral），不使用组合或肢体，只朗读：“啊，哦，呜，咦，诶。爸爸抱宝宝，妈妈买面包。胖胖的小猫，慢慢跑过木桥。一、二、三、四、五。好，到这里结束。”
2. 保持平静表情（neutral），不使用组合或肢体，只朗读：“先等一下。……好，现在继续。把第一项记下来，再看第二项。……不用着急，我们已经完成了。现在可以休息了。”

观察：声音开始后嘴巴开始活动；密集音节不一直定格张嘴；音频中真正无声的间隙嘴巴收拢；最后一个音节结束后归零。标点能否生成长停顿由语音服务决定，只按实际听到的声音验收。

当前口型使用实际音频 RMS 包络，不是逐音素口型系统；“啊、哦、呜”没有各自精准的圆唇形状不判为失败。若开启无语音模式，不能据此验收音频口型。本组用 neutral 排除表情本身的开嘴；其他组中，高兴或惊讶在停声后保留一点张嘴不一定是音频故障。

### C11：表情不能抢走语音口型（1 轮）

发送：

> 不使用开场组合或肢体。按意思从轻微疑惑转为释然，再变成开心，语音保持连贯。朗读内容：“咦，我刚才以为东西不见了，还认真找了好一会儿。原来它一直就在旁边，只是被纸挡住了。现在找到了，真好！下次我先仔细看看，免得又让自己白紧张一场。”

观察：换脸时嘴型不突然固定、不因笑脸一直张大嘴；眼睛、眉毛和嘴角能表达情绪，但开合仍随声音。若要单独检查特殊眼型，可再以开心的 >< 眼重读一次；不要要求所有特殊嘴型都具有真人发音形状。

### C12：极短回复与恢复（3 轮）

依次发送：

1. 只回答并朗读一个字：“嗯”。不要增加解释。
2. 只回答并朗读：“好，知道了。”
3. 刚才说得很简短。现在请用两句话提醒我，为什么测试时应该一次只改一个设置。

观察：前两轮不为凑动作而加字；短语音允许跳过组合，不能把跳过判为失败；第三轮能够恢复正常表现，不残留上一轮嘴型，也不漏掉声音开头。

## 四、用户交互与恢复能力

### C13：停止后立刻开始新一轮

先发送 C09。听到第一句后，在界面点击“停止”，随后发送：

> 刚才那段不用继续了。现在只朗读：“我们换个话题，你好呀。”

观察：旧声音停止；旧字幕与动作不重新冒出来；手臂允许短暂平滑回收，不能隔几秒又补播；新声音和口型能立即进入新一轮。连续做 3 次，检查是否只第一次正常。

### C14：说话过程中摸头，再单独敲盆

先发送 C09。讲述中用实体鼠标持续摸头超过 2 秒，再松开。

观察：摸头优先，能进入闭眼、绯红与双手抚胸；不应与举指抢手臂；口型仍按实际语音工作。松手后不重播已被打断的旧动作。新一轮仍可以正常举指；不是要求一松手就恢复原节点。

等说话结束，打开戴盆，在无语音时依次单击、较快连击、停止点击。随后关闭戴盆再摸头。

观察：每次有效敲击有反应，快速连击不积压成几秒后的补播；敲击瞬间惊讶张嘴属于表情，但嘴巴不能随着金属余音持续作说话开合；摘盆后摸头恢复。这个项目主要测交互仲裁与播放器，不用于评价智能体的语义理解。

### C15：隐藏、显示与输入恢复

先发送 C09。播放中隐藏桌宠，然后显示；使用实体鼠标摸头。重复隐藏/显示 3 次，再发送：

> 重新开始。用画面左侧举指，配合开心表情，不使用开场组合。只朗读：“回来了，我们继续。”

观察：恢复显示后真实点击仍然有效；旧回复不因重新显示而从头重播；新朗读、口型和交互正常。隐藏本身不是停止朗读命令，声音可能继续；需要验证取消时另按 C13 点停止。短句的手势可能来不及完整展示，因此完整左举指几何以 C06 为准。

### C16：连续对话的累积状态（8 轮）

一条一条发送，每轮按平时聊天方式简短回答，不指定表情或动作：

1. 早上好，今天精神怎么样？
2. 我刚完成了一件拖了很久的小事。
3. 不过还有一项没做好，有点可惜。
4. 先不安慰我，帮我想一个明天能执行的小步骤。
5. 这个建议为什么比一次做完所有事情更靠谱？
6. 好，我理解了。不用再解释。
7. 顺便说一句，你刚才认真解释的样子挺可爱的。
8. 那我先去忙啦，回头见。

观察：没有越来越频繁的举手、持续残留的脸红或加载状态；告别后自然收束；没有对每段都重复“想到了”；正常内容控制在短句，需要展开时再展开。隔一会儿重新做一遍，区分稳定现象与偶发抖动。

## 记录与判断

每组只给适用的维度评分。0 = 明显错误或未执行；1 = 基本正确但生硬、过量或偶发问题；2 = 正确自然；NA = 本组未测到。不要把“没来得及观察”记为通过。

| 维度 | 检查内容 |
|---|---|
| 语境 | 表情和态度是否理解真实意思，而不是仅匹配关键词 |
| 执行 | 是否调用受支持能力，左右和模式是否正确，没有用文字冒充动作 |
| 协调 | 头、身体、手臂、表情配合；肩袖、遮罩和手型无错误 |
| 时序 | 组合一次、后续承接、合理停顿、平滑退出，短句不过度表演 |
| 口型 | 声音起止与开合同步，停顿收嘴，表情和音效不抢口型 |
| 恢复 | 停止、触摸、隐藏和新回复之后无残留、无旧任务补播 |

建议每次只改一个设置或一类实现后复测相同编号。比较得分用“实得分 / 适用项满分”，不要给大量 NA 的测试算出虚假的高分。

### 出现问题时先分层

- 选错表情、误解反话、无故庆祝：优先看智能体输出的意图、标签选择和提示。
- 角色能动但悬浮聊天窗不能发送：先区分 MCP 表演通路与 DSH 聊天桥，查看 `chatAvailable` 和 `chatMessage`，不把连接故障计成语义理解失败。
- 输出的组合或肢体 ID 正确，但没有执行：看协议接收、时长门槛、手势频率、触摸优先级及播放状态。
- 指令正确、动作也启动了，但肩袖漂浮或残影：看模型参数、渲染层级和镜像归属。
- 声音自身漏字、断句奇怪：先检查 TTS 输出，不能全部归因于口型控制。
- 声音正常但嘴不动、停不下来或随敲盆音效张嘴：看音频包络及最终嘴部合成。
- 只有隐藏后点击失效，或停止后旧语音回来：优先检查桌面窗口输入或任务取消状态。

当前一次朗读选择一种独立肢体，可接在一个开场组合之后；不要把“在一句话里自由串联任意多个左右手动作”当作已有能力。自然编排也不需要每轮命中同一个表情 ID；合理、稳定、不过量比机械复现同一套动作更重要。
