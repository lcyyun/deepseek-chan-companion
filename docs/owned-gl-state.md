# 独占画布：省去外部 GL 状态快照

版本：0.22.3。日期：2026-11-03。[文档导航](README.md)

## 现场数据与结论边界

0.22.2 的目标机对照显示：固定思考时，`drawSubmit` 约43–71ms，其中 `stateSave` 约40–69ms，占94%–98%；`sdkDraw` 仅约1–3ms，模型更新约9ms。用户补充固定“想到了”也卡，而后续智能体表演流畅，且同机高清档更顺。

这些数据定位了等待发生在 SDK `saveProfile()` 调用内，但 CPU 墙钟计时仍不能单独证明 GPU 本身执行了40–69ms。不同档位每轮重启和样本较少，也不足以推广“高清一定更快”；本次复测应先保留用户机器上更顺的高清与相同缓存选择，只切换状态快照路径。

报告中“每个蒙版都保存状态”的猜测不成立：源码和实际调用计数均表明，普通思考、想到了与讲述通常每帧保存／恢复各一次；双手镜像预绘时可为两次，不是约92个蒙版各一次。每次 SDK 保存会读取14项 `getParameter`、4项 `getVertexAttrib`、5项 `isEnabled`。

## 修改方式

本应用的 canvas 由 Live2D 独占，没有 Pixi、Three 或其他绘图器共享状态。SDK 外部状态快照在这个场景中没有必要。新适配层每帧显式建立默认 FBO、视口、颜色写入、混合、深度／模板／剪裁、纹理单元、缓冲绑定及所需属性状态，再交给原 SDK 绘制和生成蒙版。

这不是简单删除调用后假定状态正确：初始化成功前仍走旧路径；未知 SDK 结构不启用；主渲染器和镜像分别管理保存／恢复边界；异常后下一帧重新初始化。销毁时恢复之前的方法。没有永久修改官方 SDK，也没有添加 `gl.finish()` 或 `flush()` 强制等待。

默认启用独占状态管理。“设置 → 性能与画质 → 保留 SDK 状态快照（兼容对照）”勾选后恢复旧路径。GPU 数据复用是另一独立实验项，本版本不擅自改变已保存的选择。通用集成若与其他引擎共享 GL 或使用外部 FBO，应使用兼容路径，不应直接套用本应用的独占假设。

## 验证

- 确定性像素回归覆盖28个场景、84次比较，全部0像素差异、参数一致、无 WebGL 错误。包括思考、加载环、双手镜像、瞳孔、敲盆，以及固定“想到了”入场／保持／收手和3200ms后语音手势交接。
- 实际绘制次数保留；独占路径的逐帧状态查询降至0。少量启动期显卡能力查询与定时诊断不能算作逐帧快照。
- 在相同2562×1368、DPR1.5、本机 RTX 4060 Laptop、均衡且关闭缓冲缓存的原生可见对照中，未包装 GL 方法的整帧平均工作：思考约8.87→8.25ms，想到了约8.69→7.98ms，讲述约8.80→8.02ms，抚胸约10.22→8.56ms；均约60帧，未观察到新增长帧。
- 本机没有目标机的40–69ms原始等待。因此上述验证证明状态查询消除、画面等价与本机整帧成本下降，**不能替代目标电脑复测或宣称其卡顿已完全解决**。

## 目标电脑复测

1. 更新并完整重启至0.22.3，保持当前更顺的高清档和同一个 GPU 数据复用选择。
2. 默认不要勾选“保留 SDK 状态快照”，分别复现固定思考和固定“想到了”，观察实际画面，并复制性能诊断。
3. 如需同机对照，只勾选兼容快照，等模型重载完成后重复相同动作和采样；不要同时切换质量或缓存。
4. 比较 `sampleFps`、实际画面、帧间隔及整帧开销。不能仅因 `stateSave` 降为0就认定成功；若等待转移到 `stateSetup`（状态初始化与清屏）、`sdkDraw` 或帧间隔，仍需继续排查。

诊断中 `ownedGlStateEnabled=true` 表示实际启用，`stateSnapshotBypasses` 表示省去的快照边界。`totalStateSaveCalls / totalStateRestoreCalls` 统计真正执行的 SDK 快照；独占路径应为0，`totalSdkDrawCalls` 仍增加。`stageCallsPerFrame` 给出相邻样本的每帧调用次数；镜像绘制可能为2。

`runId` 标识一次桌宠主进程，`renderGeneration` 标识模型页面重载。重新加载时旧样本被清空，迟到的旧页面样本会被拒绝；应等 `available=true`、至少两个完整采样窗口、请求档位与 `sample.renderQualityMode/effective` 一致后比较。主进程的 `quality.mode` 本身不依赖贴图解码；若启动时读到上一档，应先核对是否跨了旧进程，或在旧进程退出保存之前修改了配置文件。请先正常退出，再进行外部配置编辑。

维护者可用 `scripts/verify-owned-state-equivalence.cjs` 和 `scripts/benchmark-thinking-gl.cjs --preserve-gl-state=on/off --cache-mode=legacy --suite=state` 复测。性能结论使用 `--gl-profile=off`，带包装模式仅用于调用量分析；真实模型和运行记录不随仓库分发。
