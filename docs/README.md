## 当前版容易混淆的几件事

- **表演和对话是两条通路。** MCP 能控制表情、肢体和朗读，不代表桌宠聊天框已经接上 DSH。看 `chatAvailable` 判断能否发送。
- **桌宠 0.19 起推荐 DSH 原生工具模式。** 智能体正常聊天，需要表演时调用 `avatar_reply`；安装时必须先问用户选“接到已有会话”还是“新建独立会话”，不要默认。
- **自动模式只优先 DSH。** 聊天桥就绪后自动接入；只连 MCP 会提示启用 `chat: true`。DSH 断线后保持来源并等待重连，Codex 只手动选择。
- **手动选择优先。** 旧配置缺少选择记录时会保留原来源；要使用新规则，选一次“自动 · 优先 DeepSeek Harness”并保存。
- **表情、肢体、组合分开。** 当前有 25 种表情、12 组独立肢体和 12 个组合；外部智能体先读 `avatar_capabilities`，不提交文案标题代替 ID。
- **默认声音是晓伊。** 需要联网，无需 API Key。视频的诗歌剧／曼波是制作时使用的独立配音，不是桌宠默认音色。
- **隐藏和退出不同。** 右键悬浮球可隐藏／显示角色，或“退出大肥鱼”关闭整个程序。收起聊天窗不会退出。
- **设置的保存方式不同。** “设置”页的来源、声音、回复节奏需点“保存设置”；“调节”页与小表情微调即时保存。

## 验证入口

| 命令 | 用途与边界 |
|---|---|
| `npm test` / `npm run test:ci` | 无桌面、禁止子进程的自动检查；需本机回环端口及临时目录，不调用真实模型 |
| `npm run test:desktop` | Electron、窗口、输入与原生观察器检查；需正常 Windows 桌面会话和已构建界面 |
| `npm run test:all` | 上述自动检查的合集，仍不能代替真实账号和真实模型画面验收 |
| `npm run setup:live2d:restricted` / `npm run build:restricted` | 进程内准备 SDK 和构建界面，用于不能启动 esbuild 子进程的环境 |
| `npm run package` | 在 Windows x64 生成便携包，需要正常子进程权限 |

用户已经报告 DSH `0.2.1-rc.2` 干净 profile 的真实端到端验证通过。这个结果与仓库的模拟宿主、UI、渲染测试分别记录，不推断所有账号或后续 DSH 版本都已验证。当前能力及默认值以运行时接口、[package.json](../package.json)和对应源码为准。

## 维护约定

功能变化时同步更新对应专题、快速指南和 README；只有发生行为变化才写版本记录，不为纯文字修订虚增程序版本。修改后检查示例字段、命令、相对链接以及“默认值／已验证／计划”的表述。

文档中的源码链接以源码仓库目录为基准。便携包根目录及 `resources/app` 中各带一份使用文档；实现文件不一定全部随便携包提供。模型、配音权重、个人设置和 `output/` 中的视频工程不属于源码分发内容。
