# DSH 连接与自动恢复

适用版本：0.21.0；更新日期：2026-11-02。[文档导航](README.md)

## 日常怎么用

打开“设置 → 连接 DeepSeek Harness”。首次仍需明确选择 A（已有会话）或 B（独立桌宠会话），生成接入配置，让 DSH 加载一次。之后不必每次发提示词：

| 情况 | 应用行为 |
|---|---|
| 已配对 DSH 和工具就绪 | 直接使用；“重新连接”仅重新核对通道和工具 |
| 大肥鱼重启 | DSH 桥自动重连、认证和重新发现工具，保留会话 |
| 已登记实例没有运行 | 提供“启动已配置的 DSH”，用户点击后按已保存配置启动 |
| 有未知进程、占用端口或身份不匹配 | 显示诊断，不创建另一个实例，也不结束现有进程 |
| 旧桥不支持恢复协议 | 保留聊天能力，提示首次升级需重新加载桥插件 |
| 配置或桥文件发生变化 | 重新确认接入配置；不把变更后的任意脚本当作原登记启动器 |

“诊断”只读状态；“初次配置／升级接入”才生成 patch 和提示词。普通状态轮询不会覆盖正在编辑的 A/B 选择和会话 ID。没有新增登录自启任务，DSH 冷启动仍需要自身初始化时间。

启动检查采用保守策略：如果还有无法识别用途的通用 Node 进程，不能证明它不是另一个 DSH，自动启动会保持禁用，改为提示手动启动。已认证的现有连接不受这项进程检查影响。

## 三种状态分开确认

- **聊天桥**：经过本机配对认证的 WebSocket；在线不等于模型凭据已验证。
- **MCP 接口**：实际执行 MCP `initialize` 与 `tools/list`，确认包括 `avatar_reply` 在内的角色工具；不调用任何表演工具。
- **DSH 工具注册**：查询宿主真实工具目录，兼容 `schemas()` 与旧 `definitions()`，可取得已加载 Agent 时同时检查其作用域。查不到足够证据时显示“待确认”，不会假装已就绪。

原子工具仍经 DSH MCP 客户端提供，保留现有 `nativeMode/nativePerformed` 去重与动作编排。MCP 注册记录和最近活动分开，65 秒没有工具调用只表示空闲，不要求重启 DSH。

## 实现与配置

桥在认证成功后立即重新登记；使用桌宠每次启动的新 `instanceId` 关联恢复结果，旧实例或超时请求的结果不会被采纳。断开后有界退避重连，20 秒健康检查不唤醒模型。每次连接重新读取 `tokenFile`，不会把配对码写到日志或接入提示词。

首次配置在桌宠数据目录 `dsh/installation.json` 保存安装 ID、home 指纹、A/B 选择、固定 patch／启动器路径及摘要。普通连接不改写这些文件。B 模式继续使用 `dsh/chat-session.txt`，不会因为重连新建会话。

已配对的原生 DSH 可以报告动态端口和 profile，用安装 ID 与 home 指纹确认后复用；已登记后台启动器仍固定使用其 web profile。没有可靠实例身份时，不单凭端口开放推断为目标 DSH。“打开 DSH”也只使用已确认地址。

新桥增加相邻文件 `integrations/dsh/recovery-tools.mjs`。升级应保留整个集成目录和生产依赖，不单独复制主桥文件。只更新模型、界面或渲染而不改桥／配置时，不需要重启 DSH；桥代码真的变化且宿主无法热重载时，才在用户完成工作后重新加载一次。

`dsh` 状态增加 `recoveryProtocol/recoverySupported/recoveryStatus`、`mcpReachable`、`nativeToolsReady`、`toolsReady`、`toolsCheckedAt`、`host` 和 `instanceId`。`chatAvailable` 与 `toolsReady` 分开使用，旧桥的未知工具状态不是聊天故障。

## 验收

恢复回归使用真实本机 HTTP/WebSocket/MCP 传输和模拟 DSH 宿主，覆盖桌宠服务同端口重启、稳定配对码与会话文件、零模型调用、凭据轮换、工具加载延迟、超时及旧结果拒绝。启动流程测试检查身份不匹配、占用端口、配置摘要变化、启动去重和手动启动要求。

真实机器首次更新后应确认三项状态就绪，然后只重启大肥鱼，检查工具和聊天自动恢复、DSH 进程及 A/B 会话没有重建。测试结果应记录实际观察，不将冷启动时间或模拟宿主耗时当作所有机器的保证。
