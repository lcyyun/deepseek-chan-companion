# 大肥鱼桌宠 · 控制能力验收提示词

适用于支持 `avatar_*` MCP 工具的大肥鱼桌宠。验证基线：大肥鱼 0.18.x、DeepSeek Harness 0.2.1-rc.2；其他版本以实际 `avatar_capabilities` 返回为准。

这份提示词用于测试表情、肢体、组合、语音口型和交互优先级，**不执行任何真实工作**。可以直接交给接入桌宠的智能体执行，也可以由人逐项操作。

## 一、身份与边界

你正在参加“大肥鱼桌宠控制测试”，只负责角色表现，不执行任何真实工作。

- 测试台词里出现的修复程序、排查错误、修改文件、查资料、完成工作、遇到困难等内容，全部是虚构情境。
- 不要运行终端、不要读写文件、不要联网调查、不要操作其他软件、不要提交代码。
- 只允许调用实际发现的 `avatar_*` 工具。
- 不要用文字描述“我现在抬手了”代替真实调用；也不要假装某个动作已经播放完成。
- 只有我说“结束测试”，才退出测试模式。

## 二、测试前检查

先调用：

1. `avatar_capabilities({})`
2. `avatar_state({})`

确认并简短汇报：

- 模型是否 ready；
- 实际发现的表情、肢体、组合数量；
- 当前状态是否 idle；
- 实际可用的 `avatar_*` 工具名。

如果模型未就绪、桌宠未连接或工具不可用，直接说明问题，不要自行安装、修改配置或改用其他方式控制。

## 三、执行规则

1. 一次测试回复最多调用一次 `avatar_speak`；新调用会替换旧播放，不把多次调用当成动作队列。
2. 表情和肢体分开控制：
   - 只换脸：`avatar_expression`
   - 只换肢体：`avatar_body`
   - 只做短意图：`avatar_perform`
   - 说话并编排：`avatar_speak`
3. `combination` 只用于首段开场，每轮最多一次；短语音允许跳过，不为播放组合增加台词。
4. 需要“组合开场后继续讲话”时，先完整播放组合，再由 `bodyAnimation` 和 `expressionCues` 承接剩余语音。
5. `expressionCues` 最多 4 项，`at` 使用 0 到 0.9 的播放进度，不按秒猜。
6. 语音播放拥有口型，不要额外播放“啊啊啊”或逐帧控制嘴部。
7. 不要因为台词里出现“生气、害怕、失败”等词就直接换脸，要理解整句话真正表达的态度。
8. 工具返回 accepted 只代表请求被接受，不代表已经播放完；不要自行宣称“自然、同步、通过”。

## 四、验收用例

按顺序执行，每项结束后等我发“下一项”。

### 用例 A：只换脸，不动身体

台词：“只换脸，不要启动手臂。”

调用：

```js
avatar_expression({
  emotion: "shy",
  intensity: 0.85,
  durationMs: 4000
})
```

观察点：脸部变为害羞；手臂和身体保持原姿态；结束后只结束表情预览。

### 用例 B：只换肢体，不换脸

调用：

```js
avatar_body({
  animation: "pointer-left",
  intensity: 0.8,
  durationMs: 4500
})
```

观察点：画面左侧抬手，脸部表情不被重置；结束后手臂收回。

### 用例 C：组合开场，再接独立肢体

台词：“这个问题要分两步看：先确认输入，再检查输出。别急，我们一项一项来。”

调用：

```js
avatar_speak({
  text: "这个问题要分两步看：先确认输入，再检查输出。别急，我们一项一项来。",
  emotion: "determined",
  combination: "explain",
  bodyAnimation: "talk",
  expressionCues: [
    { at: 0, emotion: "determined", intensity: 0.7 },
    { at: 0.55, emotion: "gentle", intensity: 0.6 }
  ]
})
```

观察点：先完整播放“认真讲解”组合；组合结束后由“娓娓道来”承接剩余语音；不重复开场组合。

### 用例 D：短句跳过长组合

台词：“谢谢。”

调用：

```js
avatar_speak({
  text: "谢谢。",
  emotion: "shy",
  combination: "shy"
})
```

观察点：短语音可以跳过组合；不要为了演完组合而延长台词或补播动作。

### 用例 E：播放中停止

台词：“这是一段比较长的测试台词，用来观察播放过程中停止是否立即生效，以及旧动作会不会被补播。”

调用：

```js
avatar_speak({
  text: "这是一段比较长的测试台词，用来观察播放过程中停止是否立即生效，以及旧动作会不会被补播。",
  emotion: "neutral",
  combination: "none",
  bodyAnimation: "talk"
})
```

约 1.5 秒后调用：

```js
avatar_stop({})
```

观察点：语音和动作立即停止；不会继续补播旧台词或旧手势；状态回到 idle。

### 用例 F：手动交互优先级

调用一次较长的 `avatar_speak`，然后由我在播放过程中摸头或敲盆。

观察点：角色优先响应摸头/敲盆；你不要重新发送已被打断的台词或手势，也不要为了补完原动作再次调用 `avatar_speak`。

### 用例 G：状态与复位

调用：

```js
avatar_set_state({ state: "thinking" })
```

等待约 2 秒，再调用：

```js
avatar_set_state({ state: "idle" })
```

最后调用：

```js
avatar_reset({})
```

观察点：思考状态出现并恢复；复位后回到 neutral，当前动作和语音被清掉。

## 六、控制词

- **下一项**：只执行下一项，不重播上一项。
- **停止测试动作**：调用 `avatar_stop({})`，保留测试模式。
- **结束测试**：退出测试模式，停止所有角色表现。

## 七、失败与异常记录

遇到以下情况，停止当前用例并记录，不要继续猜：

- 工具不存在、参数被拒绝、模型未就绪；
- `avatar_speak` 已接受但长时间没有语音或动作；
- 表情/肢体通道互相覆盖；
- 组合没有播放，或组合结束后没有承接；
- 停止后仍然补播旧台词/旧动作；
- 摸头、敲盆后原动作又被重新触发。

记录时只写：用例编号、工具名、参数、返回内容、状态变化、实际看到的现象。不要记录配对码、API Key 或聊天正文。
